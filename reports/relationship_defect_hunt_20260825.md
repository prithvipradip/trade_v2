## Structural blind spots of this hunt (critic)

- Concurrency/ordering contracts were not a class: nothing examined interleavings between the fast monitor, scan loop, reconciler, and check_fills over the same trades row (orchestrator.py:416 gather; CAS filled->closing at :2287 vs reconciler close_trade), the loop-binding asyncio.Lock pattern in ibkr_client.py:51-53/373-378, market_data.py per-key single-flight locks vs the TTL assumptions numeric-pairs-07 only checked as numbers, or master.py:881's daemon idle-killer thread killing the bot mid-transaction. All 7 classes compared static values; race-window defects are invisible to them.
- Multi-process DB contracts: orchestrator, master.py supervisor, status.py/status_server.py, web_logs.py, and the Streamlit dashboard all open data/ait_state.db concurrently. SQLite locking mode/WAL, write ownership, and stale-read semantics between these processes were never swept — only the SQL text of the queries was.
- External-format contracts unswept: telegram.py message contract (parse_mode escaping, 4096-char truncation of the discrepancy/digest payloads), the dead-man/healthchecks ping contract (scripts/verify_deadman.py is the only requests caller found — whether master.py's ping URL/interval matches what the external monitor expects was not checked), and IBKR/ib_insync field assumptions (broker order-status strings mapped into TradeStatus, portfolio-item P&L field semantics, contract localSymbol parsing in the reconciler). A drifted broker enum here books wrong closes and no class covered it.
- Log-line format as a contract: status.py/web_logs.py/check_first_rth_liveness.py regex/substring-match structlog event names and fields out of ait.log. The time-authority class caught only the timestamp axis; event-name or field renames in src (e.g. ibkr_connected, scan_symbol_timing, trade_executed) silently zeroing those readers were not swept.
- Config-vs-documented-policy: PLAN.md, docs/, and the go-live scorecard's own definition of '50 clean IC closes' vs what master.py:1152-1321 actually counts were not compared. Given string-contracts-4 (reconciler $0 sentinels pass the not-real-close filter) and string-contracts-1 (phantoms count toward MIN_TRADES), the 50-close go-live gate itself may count rows the policy documents would exclude — the class hunt checked query-vs-query, never query-vs-stated-policy.
- Test-fixture schema drift as a class: 5 test files hand-write CREATE TABLE (test_duckdb_analytics, test_r14_batch2, test_r16_tail_fixes, test_r17_dormant_strategy_fixes, test_r21_post_stop_cooldown). Nothing compares those DDLs to state.py's real schema/migrations; test_duckdb_analytics was already proven to encode a wrong value scale, and a wrong-column sibling would pass green while production queries fail.
- Consistent-but-wrong is structurally invisible: every class confirms agreement, never validity. Both sides sharing the same wrong slippage/commission model, the same wrong option-price approximation in engine builders, or a shared constant that misdescribes market reality pass all 7 classes by construction. No absolute-ground-truth check (e.g. engine credit vs actual fill prices in executions) was run.
- Missing-counterparty policies: single-sided risks with no mirror to diverge from — early assignment/ex-dividend on short calls, gap-through-strike overnight risk vs the touch-stop model, IBKR margin/buying-power rejection paths — cannot appear as a cross-file divergence because only one (or zero) implementations exist. Given feedback_blockers.md (no-buying-power class incidents), the zero-implementation set deserved its own sweep.
- Fail-open vs fail-closed asymmetry as a class: live-bt-mirrors-02 caught one instance (calendar error: live fails closed, engine fails open), but no systematic sweep of exception paths on the other gates (earnings, liquidity, VIX fetch, range model load failure) for which side of the trade a swallowed exception lands on.
