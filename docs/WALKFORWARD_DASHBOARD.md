# Walk-Forward Lab

A static research dashboard that draws a walk-forward run: price chart with the trades on it, the Optuna search per window, and the predictor models' skill. For researchers. Not for: running research ([RESEARCH_GUIDE.md](RESEARCH_GUIDE.md)), what the models are ([MODELS.md](MODELS.md)), or the live system ([GUIDE.md](GUIDE.md)).
See also: [STUDIES_FINDINGS.md](STUDIES_FINDINGS.md) (what past studies found) · [GLOSSARY.md](GLOSSARY.md).

## 1. What it can show today

The Lab is a set of static files in `src/ait/dashboard/walkforward/` (`index.html`, JavaScript, and a generated data file `wf_data.js`). It reads **run archives**, one directory per run under `reports/runs/`, which contain:

| File | Holds | Needed? |
|---|---|---|
| `run_metadata.json` | Run settings and the per-window summary | Required: a directory without it is skipped |
| `window_NNN.json` | Per-window detail: trades with their legs and decision record, Optuna trials, model skill | Optional; without it the trade, Optuna and model tabs are thin |
| `equity_curve.csv` | Trade-level equity curve | Optional |
| `timeseries_bars.json` | Per-bar features and model predictions | Optional; without it the price chart still draws (from `data/historical.db`) but has no ML pane |

**Who writes those files:** only the older integration pipeline, `scripts/run_integration_test.py`, which archives its output with `_create_run_archive`. Whether that script currently runs is recorded in its row in [reference/SCRIPTS.md](reference/SCRIPTS.md). The current research entry points, `run_backtest.py` and `run_optimizer.py`, write a **run record**
(`run_record.json`, [RESEARCH_GUIDE.md](RESEARCH_GUIDE.md#9-studies-and-run-records)) and **do not appear in the Lab**. So today:

- The Lab can display runs made by the integration pipeline. Treat every archive already in `reports/runs/` as obsolete: they were made under earlier models, gates and friction assumptions, and no finding should be drawn from them. No `wf_data.js` is committed (it is generated by the export and git-ignored).
- It cannot display a current `run_backtest.py` / `run_optimizer.py` run. Reading those means opening the run record. (`scripts/compare_runs.py` compares integration-pipeline archives, not run records.) Adding an adapter from the run record to the Lab's format has not been done.
- A page opened without `wf_data.js` shows built-in mock data (`data.js`), so a view that looks populated is not necessarily a real run: check the experiment id and run date in the header.

## 2. Getting a run into the Lab

```bash
# one run
python -m ait.dashboard.walkforward.export --report-dir reports/runs/<run directory>

# every run directory under reports/runs/ (adds a dropdown to switch between them)
python -m ait.dashboard.walkforward.export --runs-dir reports/runs

# serve (static files, localhost only)
cd src/ait/dashboard/walkforward && python -m http.server 8080      # then open http://localhost:8080
```

`--out` overrides where `wf_data.js` is written (default: next to `index.html`). Re-run the export after each new archive and hard-reload the page (Cmd/Ctrl+Shift+R) because the browser caches the data file. With `--runs-dir`, the latest run that has trial history or model skill
becomes the default view. A directory that fails to load is skipped with a warning. The exporter reads the OHLCV bars for the chart from `data/historical.db` when it exists.

## 3. Tabs

| Tab | Answers | Needs |
|---|---|---|
| **Experiment Analysis** | How did the strategy perform, what trades were taken and why? | `run_metadata.json`; trade detail in `window_NNN.json` for legs and the decision chain |
| **Optuna Optimization** | How did the parameter search behave, and what did it pick per window? | Optuna trials in `window_NNN.json` (runs made with per-window optimisation) |
| **Predictor Models** | Do the models have skill out of sample? | Model skill in `window_NNN.json`; per-bar predictions in `timeseries_bars.json` for the chart overlay |

The header shows the run id, strategy, symbols, date range, objective, the window layout (train / test / step days) and the code version. The archive does not record the objective, so the header shows a dash for it unless a run supplied one.
A light/dark toggle sits top right and is remembered by the browser. When several runs were exported, a dropdown switches between them.

## 4. Experiment Analysis

### 4.1 Price chart and panes

Candlesticks of the symbol's daily bars. Overlays (sidebar checkboxes): SMA 20, SMA 50 and Bollinger Bands (the run's `bb_upper` and `bb_lower` features: by default the 20-day SMA ± 2 standard deviations). **Trade markers:** an up arrow below the bar is an entry (gold when pinned); a down arrow above is an exit (green profit, red loss). Click an arrow to pin the trade.

Sub-panes share the time axis and crosshair:

| Pane | Shows |
|---|---|
| ML Predictions | `P(in-range)` (the range model) and direction confidence, per bar. Blank where the model emitted nothing ([section 6.3](#63-why-predictions-go-missing)) |
| RSI (14), MACD | Momentum features |
| Realized Vol / ATR | 20-day realised volatility and ATR as a percentage of price |
| IV Rank / VIX | IV rank ([GLOSSARY.md](GLOSSARY.md)) and VIX |
| Hurst | The wavelet Hurst estimate against the 0.5 random-walk line (below 0.5 mean-reverting, above trending) |
| Sentiment / P-C | A retired feature block. The pane is offered in the sidebar only when the run carries sentiment values, which current exports do not |

The feature panes are labelled with fixed names (`rsi_14`, `sma_20`, ...). If a run used other feature windows, the series is still the run's own feature under that label.
To zoom to one test window, pick it in the sidebar and press Zoom.

### 4.2 Trades table

One row per trade with these columns, each sortable by clicking its header: **Trade** (id), **Entry**, **Exit**, **Hold** (days), **P(range)** (the range model's confidence at entry; empty when it emitted nothing), **IV rank**, **VIX**, **Regime**, **Exit reason**, **Qty** (contracts), **P&L** (dollars, as the engine booked
them) and **Return** (on the capital at risk). The filter bar has a search box (matches the trade id, exit reason, regime and entry date), an exit-reason dropdown, All / Win / Loss buttons (a trade is a win when its P&L is above zero) and a count; the window dropdown in the sidebar filters table and chart together.
Clicking a row pins the trade, zooms the chart to it and draws a price line at each strike. Exit reasons are the engine's own labels; the set the current engine produces is described in [RESEARCH_GUIDE.md](RESEARCH_GUIDE.md#5-the-engine).

### 4.3 Pinned trade drawer

Clicking a trade opens a drawer with four sections.
- **Execution:** order time, the underlying at the scan, the credit at open and cost at close per share, exit time and the underlying at exit.
- **Decision chain:** replays why the engine entered, **from the decision record stored with the trade**: the direction model's call (for a condor the page notes that the directional gate is bypassed and the range model is the entry filter); the range model's `P(in-range)` against its threshold, drawn as a gauge; the
  volatility gate (10-day realised volatility against the maximum entry volatility); the meta-label filter (take or veto); the fractal (Hurst scale-spread) gate; and the regime label recorded at entry. If the trade has no decision record at all, the page says the chain is not available. **If the record exists but a gate is missing from it, that
  step is drawn as a green "pass" with dashes for its numbers**, so read the numbers, not the colour. Which steps actually *blocked* entries depended on that run's gate mode ([MODELS.md](MODELS.md#10-gating-observe-and-enforce)): in observe mode a step can read "fail" for a trade that was taken.
- **Iron condor structure:** the legs (type, strike, premium) and the stored net credit, maximum loss and contracts.
- **Features at entry:** the feature snapshot, when the run stored one.

### 4.4 KPI strip

With "All" windows selected the strip shows the whole run: total return, Sharpe, Sortino, win rate, profit factor, maximum drawdown, consistency (the share of windows with positive P&L), expectancy, trade count with average holding days, and final capital. Selecting one window switches it to that window's out-of-sample result:
return, Sharpe, Sortino, win rate, profit factor, maximum drawdown, P&L, expectancy, trades (with average hold) and average win / average loss. Definitions are in [section 8](#8-metrics). A window with very few trades makes every ratio unreliable: read the trade count first.

## 5. Optuna Optimization

Each window can run its own parameter search; this tab shows how it behaved ([RESEARCH_GUIDE.md](RESEARCH_GUIDE.md#8-the-optimizer) explains the search itself).

- **Study status and trial breakdown.** Complete, pruned (stopped early by the pruner because intermediate results lagged the median) and not-run trials. Many pruned trials is normal; a very high share suggests the search space is wide or a few combinations dominate.
- **Objective over trials.** Each dot is a trial's objective value, with the best marked and a running-best line. A running best that is still rising at the end means the search had not converged; a wide scatter means outcomes are sensitive to the parameters.
- **Parameter versus objective.** Pick a parameter to see how it relates to the objective. A best trial sitting at the edge of the range means the search space may be too narrow.
- **Optimal parameters.** The values used for that window's out-of-sample run. They are **in-sample optima**: only the out-of-sample result beside them says whether they generalise.

## 6. Predictor Models

This tab separates "do the models have skill?" from "did the strategy make money?". Poor skill makes poor trading likely; good skill does not guarantee good trading. What the models are, how they are trained and how they are validated: [MODELS.md](MODELS.md).
**Fixed text on this tab.** The task description, member list and objective line under each predictor come from the exporter's own table (`_model_meta` in `export.py`), not from the run. They describe the models as they were when the Lab was built: the range predictor as "P(stays in ±5% over 30d)" with XGBoost, LightGBM and GARCH-family members, the direction predictor with a 0.70 confidence floor. The current models differ ([MODELS.md](MODELS.md)); trust the numbers, not these captions.

### 6.1 Direction ensemble
Reported as cross-validated AUROC (macro, one-versus-rest) per window: 0.5 is no skill, 1.0 is perfect. A value close to 0.5 means the model should not be used to gate anything; an unexpectedly high value deserves a look for look-ahead leakage. This predictor has no `P(in-range)` line: its summary tile is "No-edge windows" (below the confidence floor) instead of "Windows gated".

### 6.2 Range model
Reported as cross-validated balanced accuracy (the mean of recall on "stays in range" and "breaks out", which handles imbalanced labels) and as an **edge over 0.50**. Summary tiles: average balanced accuracy, mean edge per window, best window, windows gated, dominant member and the average in-range base rate (the naive prior; its subtitle "±5% / 30d" is fixed text on the page, not the run's band).

### 6.3 Why predictions go missing
The range model has a quality gate: when its cross-validated edge over a coin flip is below a floor (`ml.range_min_edge_over_baseline`), it returns no prediction rather than a probability it cannot back. So the **skill chart** (training scores, shown for every trained window) can show bars while the **price chart** has no `P(in-range)` line. Both are correct.
**The "gated" flag and the "Windows gated" tile are not read from the run.** The exporter classifies each window itself, as gated when its edge is below a fixed 0.10 (`RANGE_MIN_EDGE` in `export.py`), and the page prints that same figure. The floor the run's model actually used is the setting above, which can differ, so a window shaded as gated may have emitted predictions,
and the reverse. The per-bar predictions in the price chart are the run's real output.

### 6.4 Charts
- **Member skill across windows.** Grouped bars of each ensemble member's cross-validated score per window, with the 0.50 baseline dashed; gated windows are shaded. Consistent bars suggest a persistent signal; large swings suggest sensitivity to the market regime; a member near 0.50 adds noise.
- **Fitted ensemble weights.** A stacked bar of the weights the blender gave each member in each window (members with no skill get near-zero weight). Wild window-to-window swings mean noisy cross-validation scores or small training sets.
- **Calibration (reliability).** Predicted probability on the x axis against the observed frequency of "stayed in range" on the y axis, per member and for the blend; dot size is the number of samples in the bin. On the diagonal is calibrated; above it is underconfident; below it is overconfident
  (do not take a high `P(in-range)` at face value); flat means little discrimination. Calibration matters because the range probability is compared directly with a threshold.

### 6.5 Legacy panels for retired models
Archives made before the statistical volatility members (GARCH, GJR/EGARCH, Markov-switching GARCH, and the OU-Kou-GARCH jump model) were retired also carry their convergence flags, information criteria and fitted parameters, and the Lab draws an expandable detail row for each. Those members are not part of the current models
([MODELS.md](MODELS.md)), so current archives do not populate these rows, and the member colours for them appear only on old runs. The methodology papers are kept in [archive/](archive/README.md) for reference.

## 8. Metrics

| Metric | Definition |
|---|---|
| Total return | (final equity − initial equity) / initial equity |
| Sharpe | Mean return over its standard deviation, annualised by the square root of trades per year (capped at the daily value), because a trade is not a trading day. It differs from a daily-return Sharpe; compare only within the Lab |
| Sortino | As Sharpe, with the deviation taken on losing returns only |
| Win rate | Trades with P&L above zero / all trades |
| Profit factor | Gross wins / gross losses |
| Maximum drawdown | Largest peak-to-trough fall in equity, as a fraction of the peak |
| Expectancy | Mean P&L per trade |
| Consistency | Share of windows with positive P&L |
| AUROC | Area under the ROC curve; 0.5 is random |
| Balanced accuracy, edge | Mean of recall on both classes; edge is that minus 0.50 |
| BIC | Bayesian information criterion (legacy panels) |
| Hurst exponent | Long-range dependence: below 0.5 mean-reverting, above 0.5 trending |
| IV rank, P(in-range), in-range rate | See [GLOSSARY.md](GLOSSARY.md) and [MODELS.md](MODELS.md) |

How a walk-forward run cuts its windows (train, purge gap, test, step) and what the engine assumes: [RESEARCH_GUIDE.md](RESEARCH_GUIDE.md#3-what-one-run-does).
